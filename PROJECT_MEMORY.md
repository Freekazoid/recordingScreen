## 3. AS-IS архитектура (кратко)

Приложение — **монолитный Tkinter-процесс**, который сам делает всё:
UI, выбор устройств, захват, кодирование, настройки, постобработку и запуск
ML-моделей. Фоновые задачи вынесены в `multiprocessing`, но состояние задач
не сохраняется.

```
Tkinter UI (gui_window.py, ~2000 строк)
  ├─ захват видео: full_screen.py, area_screen.py, program_screen*.py
  ├─ захват аудио: audio_recorder.py (ffmpeg + pactl/pw-record/WASAPI/AVFoundation)
  ├─ настройки: settings_manager.py + settings.json
  ├─ фон: background_tasks.py (multiprocessing)
  │    ├─ склейка: merge_save.py
  │    └─ ASR/диаризация: audio_transcriber_service.py (~1850 строк)
  └─ модели: model_manager.py
```

### Факты, важные для переписывания

- Основной объём: `gui_window.py` — 2008 строк, `audio_transcriber_service.py` — 1852, `audio_recorder.py` — 1173, `program_screen_wayland.py` — 1005.
- Почти все модули импортируются плоско (`from app_paths import ...`), без пакета; сборка держится на `--hidden-import`.
- Захват видео и аудио — отдельные подпроцессы ffmpeg/OpenCV, синхронизация по времени старта, а не по общим PTS.
- Видео пишется через OpenCV `VideoWriter` (XVID) в `output.mkv` **относительно текущего каталога**.
- Аудио пишется в `audio.wav` **относительно текущего каталога**; временные файлы — `.temp_segments`, `.temp_postprocess` тоже в CWD.
- Настройки — плоский JSON без версии схемы; нормализация поддерживает только `str`/`bool`.
- Логи — текстовые, без корреляции session/job; подробный лог только в debug-режиме.
- Нет БД, нет истории сессий, нет восстановления после падения.
- Нет автоматических тестов захвата/ASR; CI делает только `compileall`.

## 4. Проблемы, которые признаны пользователем

### P0. Запись тишины / «пустая» транскрипция

**Симптом:** файл создаётся, но в нём тишина; транскрипция выдаёт пустой
результат или сообщение «аудио не содержит различимого сигнала».

**Вероятные причины (подтверждать диагностикой):**

1. Выбран не тот monitor-источник или `pw-record --target 0` захватывает не тот узел.
2. Микрофон выключен/замьючен, либо macOS не дала доступ к микрофону.
3. Устройство вывода переключилось после старта (Bluetooth/HDMI), запись продолжилась с «пустого» узла.
4. Микширование `amix` с `normalize=0` и `volume=12dB` даёт клиппинг или, наоборот, тишину при разных уровнях.
5. Нет проверки фактического сигнала после старта: код считает запись успешной, если процесс ffmpeg жив (`process_main is not None`).
6. Порог `_is_silent` (RMS `5e-4`) отсекает тихую, но валидную речь.
7. Жёстко задан `language="ru"`; для другого языка результат может быть пустым/мусорным.

**Где смотреть:** `src/audio_recorder.py:970-1118`,
`src/gui_window.py:1715-1745`, `src/audio_transcriber_service.py:459-472,
1071-1107`.

### P1. Спикеры разделяются нестабильно

**Симптом:** один человек помечен как два, два — как один; метки «прыгают»
между репликами; на смешанной дорожке диаризация ошибается.

**Причины:**

1. Микрофон и системный звук **смешиваются до ASR** — теряется самый сильный
   признак «локальный/удалённый участник».
2. `_normalize_speaker_segments` эвристически переставляет/склеивает метки,
   может «улучшать» неверный результат.
3. `_build_speaker_transcript` распознаёт каждый сегмент диаризации отдельно —
   короткие сегменты теряют контекст, растёт WER.
4. NeMo Sortformer ограничен 4 спикерами; между окнами метки сопоставляются
   эвристикой `_merge_windowed_segments`.
5. Нет обработки перекрытий, нет enrollment/имён, нет ручной коррекции.
6. Vosk вообще отключает диаризацию (это ограничение движка, но сообщение
   появляется только в логе).

**Где смотреть:** `src/audio_transcriber_service.py:261-435, 1071-1469`,
`src/audio_recorder.py:804-840`.

### P2. Права на запись и пути

**Симптом:** на одной машине работает, на другой — «permission denied»,
файлы появляются не там, приложение не находит результаты.

**Причины:**

1. `os.listdir('.')` и фиксированные `output.mkv`/`audio.wav` — всё зависит
   от текущего каталога. Запуск из меню/ярлыка может дать CWD `/` или `$HOME`.
2. Запись идёт рядом с программой (`bin/`, `logs/`, `model/`), а в AppImage/
   `/Applications`/`Program Files` это read-only.
3. `writable_bin_dir()` при неудаче всё равно пытается создать каталог и
   может бросить исключение.
4. Нет проверки прав на выбранный `output_dir` до начала записи.
5. macOS TCC (микрофон/экран), Wayland-портал, Windows SmartScreen —
   обрабатываются частично и без внятных инструкций.

**Где смотреть:** `src/app_paths.py`, `src/ffmpeg_locator.py:104-125`,
`src/gui_window.py:1403-1452`, `src/full_screen.py:34`,
`src/area_screen.py:498`, `src/program_screen.py:422`,
`src/program_screen_wayland.py:643`.

### P3. Запуск на разных ОС

**Симптом:** сборка/запуск отличается по платформам; часть функций есть
только на Linux; Windows/macOS — «частичная поддержка».

**Причины:**

1. Linux-специфичные модули импортируются без ленивой загрузки; сборка
   держится на `--hidden-import`.
2. Wayland-идентичность через `systemd-run` (`portal_identity.py:75-91`) —
   зависимость от systemd; на других системах портал отказывает.
3. macOS: системный звук только через BlackHole; нет ScreenCaptureKit/
   CoreAudio tap.
4. Windows: `dshow`/`pyaudiowpatch`, хрупкие имена устройств; onefile-сборка
   (Linux/macOS уже onedir).
5. CI проверяет только синтаксис (`compileall`), не запускает приложение.
6. Версии Python расходятся: dev 3.14, CI 3.11; ML-колёса под 3.14 нестабильны.
7. Сборка >2 ГБ из-за CUDA; GitHub режет на части.

### P4. Надёжность и сопровождаемость

- Нет истории сессий и восстановления после падения.
- Обработка запускается в дочернем процессе, но очередь/статус живут в памяти.
- `gui_window.py` смешивает UI, бизнес-логику и работу с ФС.
- Настройки без версии схемы; добавление числа/списка требует правок в
  `settings_manager`.
- Нет метрик WER/DER и регрессионного корпуса.
- `release.yaml` в корне — чужой/устаревший шаблон (Rust/hecate), не связан
  с реальным `.github/workflows/release.yml`.
- `main.py` использует `shutil.rmtree` без импорта `shutil`; ошибка глотается,
  очистка temp не выполняется.
- В ветке faster-whisper не вызывается `cleanup()` временных каталогов.

## 5. Целевая архитектура (TO-BE) — кратко

**Полный rewrite в версии 4.0.** Legacy 3.x остаётся рабочей веткой/тегом;
новый код развивается в `rewrite/v4`. Микросервисы не используем: это
десктопное приложение.

```
Rust Native UI (egui/eframe)
   ↕ прямые вызовы AppController + события
Rust Core (domain + application + adapters)
   ├─ capture: X11 / Wayland / WGC / ScreenCaptureKit / ffmpeg
   ├─ media: ffmpeg/ffprobe, loudness, mux
   ├─ storage: SQLite (WAL) + filesystem
   ├─ platform: paths, permissions, tray, updater
   └─ sidecar supervisor
   ↕ JSON-RPC 2.0 over stdio
Python ML sidecar (3.12): faster-whisper, pyannote, Vosk
```

**Почему Rust + egui:** нативный UI без WebView, MIT/Apache-лицензия,
малый бинарник, хорошая интеграция с Rust-ядром. Slint отклонён из-за
GPLv3/коммерческой лицензии, iced — из-за меньшего набора готовых
компонентов для таблиц/редактора. Go + Wails — альтернатива, но для
WGC/ScreenCaptureKit/PipeWire в Go потребуется больше cgo/внешних утилит.

### Ключевые принципы

1. **Сначала запись, потом обработка.** Сырые дорожки не теряются.
2. **Раздельные дорожки.** Системный звук и каждый микрофон пишутся в
   отдельные WAV. Микс — только для экспорта.
3. **Channel-aware транскрипция.** Системная дорожка — удалённые спикеры,
   микрофон — локальные. Это резко улучшает и тишину, и диаризацию.
4. **Единый каталог данных.** `dirs`/XDG/AppData/Application Support;
   никаких записей в CWD/каталог установки.
5. **Job-модель с SQLite.** Состояние сессии/шагов сохраняется; обработка
   возобновляемая и идемпотентная.
6. **Preflight.** Перед записью: права, устройства, 1-секундная проба,
   уровень сигнала, диск, ffmpeg, разрешения ОС.
7. **ML изолирован.** Python sidecar не знает про UI и файловую систему
   пользователя; только вход/выход по контракту.
8. **Offline-first.** Облако — опциональный адаптер, не зависимость.
9. **Сборка: Rust-бинарник + отдельный sidecar + модели.** CPU по умолчанию,
   GPU-пак — опционально; подпись и notarization.
10. **Качество измеряется.** WER/DER, доля успешных записей, crash-free.

### Целевой стек

| Слой | Выбор | Почему |
|---|---|---|
| Ядро | **Rust** (Tokio, serde, thiserror, tracing) | Скорость, безопасность, нативные API |
| UI | **egui/eframe** (MIT/Apache-2.0) | Нативный UI без WebView, быстрый, простой |
| ML | **Python 3.12 sidecar** | faster-whisper/pyannote/Vosk, проверенные алгоритмы |
| IPC | **JSON-RPC 2.0 over stdio** | Простой контракт, тестируемость, без сети |
| Захват видео | Rust-адаптеры + ffmpeg (X11, PipeWire, ddagrab, SCK) | Нативные API + fallback |
| Захват аудио | Rust/платформенные API + ffmpeg (PipeWire, WASAPI, CoreAudio) | Раздельные дорожки |
| Энкодер | ffmpeg/ffprobe | Один инструмент, предсказуемый результат |
| БД | SQLite (WAL) + `sqlx`/`rusqlite` | Локально, транзакции, история |
| Пути | `dirs`/`directories` | XDG/AppData/Application Support |
| Секреты | Rust `keyring` | Не хранить HF-токен в plaintext |
| Сборка | `cargo-packager` + PyInstaller onedir для sidecar | Per-OS installers, подпись |
| CI | GitHub Actions matrix: cargo, pytest | Проверка на трёх ОС |

### Что меняется в продукте

- Экран записи с **индикаторами уровня по каждой дорожке** и кнопкой «Проверить звук».
- История записей: статус, повторная обработка, открыть папку.
- Редактор транскрипта: переименование спикеров, split/merge, переход по времени.
- Диагностика: «почему тихо», «почему нет прав», «какой бэкенд используется».
- Экспорт: TXT, MD, SRT, VTT, JSON, DOCX (по этапам).

## 7. Ограничения проекта

Из `AGENTS.md` (обязательно соблюдать):

- **Не менять системные настройки/сервисы** тестовой машины: systemctl,
  D-Bus, xdg-desktop-portal, gsettings/dconf, пакеты, `/usr`, `/etc`.
- Все проблемы решать **внутри приложения**: fallback, retry, self-check,
  понятные сообщения.
- Не менять файлы вне проекта и `/tmp/opencode` без явной просьбы.
- Комментарии и докстринги — **на русском**; у функций/классов короткий
  докстринг.
- Не добавлять `Co-Authored-By` и трейлеры авторства в коммиты.
- Читать систему (`journalctl`, `ps`, `gsettings get`) можно.

Дополнительные ограничения:

- Приложение должно работать **без root** и без предварительной настройки ОС.
- Основная валюта — локальная обработка; данные не уходят в облако без согласия.
- Модели и лицензии: PyAnnote (HF token/условия), NeMo (лицензия NVIDIA),
  ffmpeg (LGPL/GPL в зависимости от сборки), egui/eframe (MIT/Apache) —
  проверить перед релизом.
- Тестовая машина — Linux; Windows/macOS проверяются в VM/CI, а не «на глаз».

## 8. Метрики успеха v4

| Метрика | Цель |
|---|---|
| Успешные записи (без пустого звука) | ≥ 99% |
| Ошибки прав/путей при старте | 0 в релизной сборке |
| Crash-free sessions | ≥ 99% |
| WER на чистой русской речи | ≤ 10% |
| DER на 2–4 спикерах | ≤ 15% |
| Ложное «тишина» на валидной тихой записи | ≤ 2% |
| Старт приложения (cold) | ≤ 3 с (без загрузки модели) |
| Обработка 1 ч аудио на CPU | ≤ 0.5× реального времени (цель) |
| Размер базового установщика | ≤ 600 МБ без моделей/CUDA |
