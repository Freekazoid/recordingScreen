# План тестирования Screen Recorder 4.0

> **Статус:** Accepted (стек Rust + native UI egui + Python sidecar)
> **Дата:** 2026-11-04
> **Связанные документы:** `roadmap.md`, `02-architecture-v2.md`,
> `03-adr.md`

---

## 1. Цели

1. Не допустить регрессий текущих проблем: тишина, спикеры, права, запуск.
2. Проверять не только код, но и **качество распознавания** (WER/DER).
3. Сделать кроссплатформенность проверяемой в CI и на VM.
4. Дать разработчику быстрый сигнал (unit/contract) и релизу — уверенность
   (E2E/smoke).

---

## 2. Пирамида тестов

```
                 ┌──────────────────────────┐
                 │ E2E / smoke (3 ОС)       │  мало, дорого
                 ├──────────────────────────┤
                 │ Integration              │  Rust + ffmpeg + sidecar
                 ├──────────────────────────┤
                 │ Contract                 │  JSON-RPC, DTO, capture
                 ├──────────────────────────┤
                 │ Unit                     │  Rust/TS/Python
                 └──────────────────────────┘
```

| Уровень | Что проверяет | Инструменты | Где |
|---|---|---|---|
| Unit | Домен, state machines, пути, merge | `cargo test`, `egui_kittest`, pytest | CI все ОС |
| Contract | JSON Schema, JSON-RPC, DTO | `insta`, `jsonschema`, pytest | CI |
| Integration | Запись+ffmpeg+job на синтетике | Rust integration tests | CI Linux, VM |
| E2E | Реальная запись/обработка/UI | `egui_kittest`, ручной чек-лист | self-hosted/ручной |
| Quality | WER/DER на корпусе | `jiwer`, `pyannote.metrics` | nightly/release |

## 3. Unit-тесты

### 3.1 Rust domain

- `SessionState` переходы: допустимые/недопустимые.
- `Track`/`SessionManifest` serde round-trip, версии.
- `TranscriptMerger`: непересекающиеся, перекрытия, эхо, порядок.
- `Speaker` mapping: `sys:S1` + `mic:S1` → отображаемые имена.
- `Job` retry/backoff, идемпотентность шагов.
- `AppError`: коды, `retryable`, сообщения.

### 3.2 Rust paths/settings

- `PathService` для Linux/Windows/macOS (подменяем `dirs`).
- `ensure_writable`: успех, read-only, нет места, ACL.
- Запрет CWD/install: тест-страж обходит код и падает при записи.
- Миграции настроек: v1 → v2, неизвестные ключи, битый JSON.
- Секреты: keyring mock, redaction.

### 3.3 Rust capture/media

- `SilencePolicy`: адаптивный порог (тишина/шум/тихая речь).
- `AudioMix`: уровни, clipping, dual-mono.
- `FfmpegArgs`: экранирование путей, форматы, CRF.
- `SegmentConcat`: порядок, пропуски, битые сегменты.

### 3.4 Rust UI (egui)

- UI-состояния: idle/recording/processing/error.
- Форматирование таймкодов/спикеров.
- i18n: отсутствие хардкода строк.
- Валидация форм настроек.
- Обработка событий `recording.level`/`job.progress` (троттлинг).

### 3.5 Python sidecar

- `hello`/protocol version.
- Парсинг/валидация JSON-RPC.
- ASR-адаптер на tiny-модели/моке.
- VAD/тишина.
- Диаризация на коротких фикстурах.
- Ошибки/таймауты/отмена.

## 4. Contract-тесты

### 4.1 Rust ↔ Python JSON-RPC

- Все методы: `hello`, `asr.transcribe`, `diarize.run`, `speaker.embed`,
  `models.status`, `cancel`, `shutdown`.
- Схемы запросов/ответов в `contracts/`; golden examples.
- Несовпадение `protocol_version` → понятная ошибка.
- Прогресс/notifications не ломают поток.
- Неизвестный метод → JSON-RPC error.

### 4.2 `AppController`

- DTO serde round-trip.
- Ошибки command → `AppErrorDto` с кодом/подсказкой.
- Нет произвольных путей/шелла в аргументах.
- События соответствуют схеме.

### 4.3 Capture

- `probe()` возвращает `Capabilities` и не падает без устройства.
- `start/stop` создаёт валидный файл на моке/виртуальном устройстве.
- Ошибка прав → `AppError(code=E_PERM_*)`, не panic.
- Смена устройства → событие/предупреждение.

### 4.4 Storage

- SQLite миграции, WAL, конкурентный claim.
- Атомарная запись артефактов, чек-суммы.
- Восстановление `running → queued`.

## 5. Integration-тесты

### 5.1 Запись

- Синтетический источник (тестовый генератор видео/аудио) → 10 с.
- Проверка: файлы существуют, ffprobe валиден, длительность ±0.5 с,
  дорожки не пустые, offset ≤ 100 мс.
- Kill -9 через 5 с → recovery находит сегменты.
- Read-only output dir → fallback/ошибка с кодом.
- Тихая одна дорожка → остальные валидны.

### 5.2 Обработка

- Короткий клип 30 с: normalize → VAD → ASR (tiny/mock) → diarization
  (mock) → merge → export.
- Повторный запуск: шаги пропускаются, артефакты не дублируются.
- Битый вход: понятная ошибка, нет partially written файлов.
- Отмена job: процесс завершается, состояние `cancelled`.
- Падение sidecar: restart, job возвращается в очередь.

### 5.3 Экспорт

- mp4/mkv/webm/avi/mov/flv; аудио copy/aac/none.
- Проверка: видео играется, аудио есть/нет, длительность, размер.
- SRT/VTT: таймкоды, спикеры.

## 7. Регрессионные тесты под текущие дефекты

| ID | Дефект | Тест | Критерий |
|---|---|---|---|
| REG-01 | CWD read-only | запуск из `/`, запись 5 с | нет ошибок, файлы в data dir |
| REG-02 | Output dir read-only | выбрать read-only папку | понятная ошибка + fallback |
| REG-03 | Микрофон замьючен | запись 10 с | system транскрибируется, предупреждение |
| REG-04 | Системный звук тихий | запись 10 с | mic транскрибируется |
| REG-05 | Обе дорожки тихие | запись 10 с | `FAILED` с кодом, без краша |
| REG-06 | Смена default sink | запись 20 с, переключить | предупреждение/переключение |
| REG-07 | Wayland portal denied | отказ в диалоге | сообщение + fallback |
| REG-08 | macOS mic denied | отказ TCC | сообщение + инструкция |
| REG-09 | Kill -9 при записи | kill через 10 с | recovery, файл валиден |
| REG-10 | Kill -9 при обработке | kill в ASR | job возобновляется |
| REG-11 | 2 спикера (system/mic) | 30 с диалог | метки «Я/Собеседник» |
| REG-12 | 4 спикера mixed | 60 с | DER ≤ 15% |
| REG-13 | Тихая речь | −45 dBFS | текст не пустой |
| REG-14 | Другой язык | английский 30 с | язык определён, текст валиден |
| REG-15 | Эхо без наушников | mic ловит system | дубли не показываются |
| REG-16 | Sidecar crash | kill sidecar | restart, job продолжается |
| REG-17 | Contract mismatch | sidecar protocol=0 | понятная ошибка, не краш |

## 8. Корпус и метрики качества

### 8.1 Состав корпуса

| Файл | Спикеры | Условия | Длительность |
|---|---|---|---|
| ru-2-clean | 2 | микрофон + системный, чисто | 10 мин |
| ru-3-meeting | 3 | созвон, паузы, перекрытия | 10 мин |
| ru-4-noisy | 4 | шум, разные микрофоны | 10 мин |
| ru-quiet | 1–2 | тихая речь, −45 dBFS | 5 мин |
| en-2-clean | 2 | английский | 5 мин |
| mixed-overlap | 3 | активные перекрытия | 5 мин |

Разметка: текст (эталон), RTTM для спикеров, границы.

### 8.2 Метрики

- **WER** = (S + D + I) / N, `jiwer`.
- **DER** = (FA + Miss + Confusion) / Total, collar 0.25 с, ignore overlap.
- **Speaker count error** = |predicted − true|.
- **Silence false positive** = валидная тихая запись, помеченная тишиной.
- **RTF** = время обработки / длительность аудио.

### 8.3 Пороги (Gate G4)

- WER ≤ 10% (чистая русская речь).
- DER ≤ 15% (2–4 спикера).
- Тишина: false positive ≤ 2%.
- Язык: auto определяет ru/en на корпусе ≥ 95%.

> Пороги — цели. Если baseline хуже, фиксируем факт и улучшаем итеративно,
> а не подгоняем метрику.

## 9. Тестовые данные и изоляция

- Фикстуры — в `tests/fixtures` (короткие, лицензионно чистые).
- Большие модели — не в git; CI скачивает tiny/заменяет mock.
- Каждый тест — свой temp dir; никаких записей в CWD.
- Сеть — mock/offline; тесты не должны зависеть от HF.
- Время — `FakeClock`; не спать в тестах.
- Процессы — таймауты, гарантированная очистка.
- Sidecar в тестах — mock-сервер или tiny-модель.

## 11. Ручные сценарии (чек-лист)

### Linux Wayland

- [ ] Запуск из `.desktop` (не из терминала) → портал показывает диалог.
- [ ] Отказ в портале → понятное сообщение, приложение не падает.
- [ ] Смена монитора/масштаба → запись корректна.
- [ ] Наушники/колонки → system/mic раздельно.

### Windows

- [ ] Установка per-user без admin.
- [ ] SmartScreen не блокирует подписанный EXE.
- [ ] WASAPI loopback пишет системный звук.
- [ ] Смена устройства по умолчанию → предупреждение.
- [ ] Длинный путь/кириллица в имени файла.

### macOS

- [ ] Первый запуск → TCC-диалог микрофона.
- [ ] Screen Recording permission → инструкция.
- [ ] Системный звук через CoreAudio tap/BlackHole.
- [ ] Notarization: приложение открывается без Gatekeeper-обхода.
- [ ] Retina/масштабирование.

| Severity | Пример | Реакция |

`--diagnose` отчёт.

## 13. Definition of Done для тестов

- [ ] Тест воспроизводит дефект до фикса и проходит после.
- [ ] Тест не зависит от сети/реального времени/устройств (где возможно).
- [ ] Тест изолирован и убирает за собой.
- [ ] Есть маркер `slow`/`e2e` для тяжёлых.
- [ ] Метрика качества обновлена, если менялся пайплайн.
