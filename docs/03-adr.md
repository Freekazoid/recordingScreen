# Architecture Decision Records (ADR) — Screen Recorder 4.0

> Формат: Context → Decision → Consequences → Alternatives.
> Статус: `Accepted` после решения пользователя от 2026-11-04; `Proposed` —
> требует подтверждения. Изменение решения оформляется новым ADR, старый не
> удаляется.

## ADR-001 — Полный rewrite в версии 4.0

**Статус:** Accepted
**Дата:** 2026-11-04

### Контекст

MVP 3.2.194 работает, но проблемы тишины, спикеров, прав и кроссплатформенности
следующие из архитектуры: CWD-пути, смешанная аудиодорожка, отсутствие
preflight и job-модели, Tkinter-монолит. Пользователь выбрал полный rewrite
с учётом существующего кода.

### Решение

Начать новую мажорную версию **4.0** в ветке `rewrite/v4`. Legacy 3.2.194
сохраняется тегом и остаётся рабочей. Переиспользуем проверенные части
(Python ML-алгоритмы, ffmpeg-команды, логику портала, настройки, тесты), но
не копируем проблемные (UI, CWD, микс, глобальное состояние).

### Последствия

- Плюсы: чистая архитектура, можно выбрать Rust + native UI, нет груза legacy.
- Минусы: дольше до первого релиза; нужны новые тесты и сборка.
- Митигация: Linux-first MVP, gates, переиспользование ML.

### Альтернативы

- Инкрементальный strangler: дешевле, но сохраняет legacy-ограничения.
- Только критические фиксы: не решает системные причины.

## ADR-002 — Раздельные аудиодорожки; микс только для экспорта

**Статус:** Accepted
**Дата:** 2026-11-04

### Контекст

В 3.x микрофон и системный звук смешиваются в один WAV до ASR
(`audio_recorder.py:804-840`). Это уничтожает признак «локальный/удалённый»,
ухудшает диаризацию, делает тишину одной дорожки неотличимой от тишины всей
записи и создаёт клиппинг/дисбаланс (`amix` + `volume=12dB`).

### Решение

Писать отдельные дорожки:
- `system.wav` — системный звук/loopback;
- `mic-<device>.wav` — каждый микрофон;
- `mix.wav` — производная (dual-mono system L / mic R);
- `screen.mkv` — видео.

ASR/диаризация — по дорожкам; микс — только для экспорта/fallback.

### Последствия

- Плюсы: channel-aware диаризация, устойчивость к тишине одной дорожки,
  диагностика, качество текста.
- Минусы: больше файлов/места; merge таймлайнов; эхо без наушников.
- Митигация: AEC/дедупликация, рекомендация наушников, mixed-fallback.

### Альтернативы

- Один микс: проще, но ломает спикеров.
- Dual-mono в одном файле: компромисс, хуже для ASR/импорта.

## ADR-003 — Job-модель на SQLite + файловые артефакты

**Статус:** Accepted
**Дата:** 2026-11-04

### Контекст

В 3.x постобработка живёт в памяти и дочернем `multiprocessing`; при
падении/закрытии job теряется. Нет истории сессий.

### Решение

`Session`, `Job`, `JobStep` в SQLite (WAL) + файловые артефакты с
чек-суммами. Каждый шаг идемпотентен; очередь — таблица `jobs`; worker —
Tokio-задача/процесс; восстановление при старте.

### Последствия

- Плюсы: возобновление, история, ретраи, прогресс, аудит.
- Минусы: схема/миграции, больше кода.
- Нейтрально: Redis/Celery не нужны.

### Альтернативы

- JSON-файлы на сессию: проще, но нет атомарности/запросов.
- Внешняя очередь: избыточно для десктопа.

## ADR-004 — Rust core + нативный UI (egui) + Python ML sidecar

**Статус:** Accepted (Rust + egui; Go + Wails — альтернатива)
**Дата:** 2026-11-04

### Контекст

Нужны скорость, кроссплатформенность и нативные capture/audio API. При этом
ML-стек (faster-whisper, pyannote, Vosk) — Python; переписывать его на Rust
или Go нерационально.

### Решение

Трёхчастная архитектура:
1. **Rust core** — домен, capture, ffmpeg, SQLite, пути, job-модель, IPC.
2. **Нативный UI (egui/eframe)** — прямой вызов `AppController`, события.
3. **Python 3.12 sidecar** — только ML, JSON-RPC over stdio.

Контракты — JSON Schema, версионирование протокола. UI-слой изолирован:
при необходимости его можно заменить (iced/Slint) без изменения ядра.

### Последствия

- Плюсы: быстрый UI/ядро, изоляция ML, можно менять UI/ML независимо.
- Минусы: два языка (Rust + Python), сборка sidecar, IPC-тесты.
- Митигация: контракты, golden JSON, CI на трёх ОС, `egui_kittest`.

### Альтернативы

- Чистый Python + PySide6: проще, но возвращает проблемы 3.x и медленнее.
- Чистый Rust: ML-экосистема незрелая, долго.
- Go + Wails: проще язык, но слабее native capture/audio.
- Tauri: WebView-зависимости, не нативный UI.

## ADR-005 — Нативный Rust UI (egui/eframe)

**Статус:** Accepted
**Дата:** 2026-11-04

### Контекст

Tkinter ограничен в диалогах, таблицах, доступности и виде. Пользователь
выбрал нативный Rust UI без WebView. Нужен кроссплатформенный, лёгкий,
достаточно зрелый для таблиц/форм/редактора.

### Решение

**egui/eframe** (MIT/Apache-2.0):
- `egui_extras` — таблицы/изображения;
- `rfd` — нативные диалоги;
- `tray-icon`, `global-hotkey` — трей/горячие клавиши;
- `rust-i18n`/`fluent` — локализация;
- `egui_kittest` — UI-тесты.

UI вызывает только `AppController`, не трогает адаптеры/ФС. События —
через каналы + `request_repaint()`.

### Последствия

- Плюсы: без WebView, малый размер, простая интеграция с Rust, MIT/Apache.
- Минусы: внешний вид не platform-native; доступность/AccessKit слабее
  Qt; rich-text редактор придётся делать самим.
- Митигация: ранние прототипы, `egui_kittest`, запасной iced; UI-слой
  изолирован.

### Альтернативы

- Tauri: WebView-зависимости, CSP, не нативный UI.
- Slint: GPLv3/коммерческая лицензия конфликтует с MIT.
- iced: MIT, нативнее, но меньше готовых компонентов для таблиц/редактора.
- Tkinter: дешево, но UX/доступность.

## ADR-006 — Offline-first + опциональное облако

**Статус:** Accepted
**Дата:** 2026-11-04

### Контекст

Записи рабочих встреч чувствительны; не у всех есть GPU. Облако может дать
качество/скорость, но требует согласия и сети.

### Решение

По умолчанию — локальные модели. Облачный ASR/диаризация — отдельные
адаптеры за портами, выключены по умолчанию, включаются явно, с
предупреждением о передаче данных. Local fallback всегда доступен.

### Последствия

- Плюсы: приватность, офлайн, нет обязательных затрат.
- Минусы: качество/скорость зависят от железа; cloud-путь тестируется
  отдельно.
- Нейтрально: локальный fallback всегда есть.

### Альтернативы

- Только облако: ломает офлайн/приватность.
- Только локально: не даёт выбора пользователю.

## ADR-007 — Единый data dir; запрет записи в CWD/install

**Статус:** Accepted
**Дата:** 2026-11-04

### Контекст

В 3.x `output.mkv`, `audio.wav`, `.temp_*` пишутся в CWD; UI ищет файлы
через `os.listdir('.')`; `ffmpeg_locator` пытается писать в `bin/` рядом с
приложением. Отсюда «permission denied», потерянные файлы и чужие записи.

### Решение

`PathService` (Rust `dirs`/`directories`) — единственный источник путей.
Данные — в data/cache/logs/temp; output — валидированный пользовательский
каталог (по умолчанию `~/Videos/ScreenRecorder`). Запись в install dir
запрещена; portable — только явно и с write-probe.

### Последствия

- Плюсы: нет прав-сюрпризов, файлы предсказуемы, чистая установка.
- Минусы: миграционное чтение старых путей.
- Нейтрально: пользователь может выбрать output.

### Альтернативы

- Рядом с программой: ломается в AppImage/Program Files/Applications.
- CWD: зависит от ярлыка.

## ADR-008 — Channel-aware диаризация + pyannote

**Статус:** Accepted
**Дата:** 2026-11-04

### Контекст

В 3.x диаризация работает на смешанной дорожке, затем эвристически
сглаживает метки и транскрибирует короткие сегменты отдельно. Результат
нестабилен; NeMo ограничен 4 спикерами.

### Решение

1. Channel-aware: system → удалённые, mic → локальные.
2. Основная модель — pyannote community-1/3.1 (`exclusive`, ограничения
   спикеров, overlap-политика).
3. NeMo Sortformer — опциональный адаптер.
4. Эвристическое сглаживание — opt-in с логом.
5. Enrollment/ручное переименование.
6. DER на корпусе — gate.

### Последствия

- Плюсы: лучше DER, меньше путаницы, прозрачные метки.
- Минусы: HF-токен/лицензия, тяжёлые зависимости, эхо без наушников.
- Нейтрально: mixed-fallback сохраняется.

### Альтернативы

- Только pyannote на миксе: хуже и дороже.
- Только Sortformer: 4 спикера, эвристики.
- Эвристическая кластеризация: только fallback.

## ADR-009 — Нативные capture-адаптеры с ffmpeg-fallback

**Статус:** Accepted
**Дата:** 2026-11-04

### Контекст

В 3.x Linux-пути доминируют; Windows/macOS частичны; Wayland-портал зависит
от `systemd-run`; macOS system audio требует BlackHole.

### Решение

Порты `ScreenCapture`/`AudioCapture`; per-OS адаптеры:
- Linux X11: `x11grab`/`xcap`; Wayland: portal + PipeWire; fallback `wf-recorder`.
- Windows: WGC (нативный) или DXGI `ddagrab`; fallback `gdigrab`;
  WASAPI loopback/capture.
- macOS: ScreenCaptureKit; CoreAudio tap или BlackHole; fallback
  `avfoundation`.

Каждый адаптер проходит `probe()` и возвращает `Capabilities`.

### Последствия

- Плюсы: качество/стабильность на каждой ОС; понятные fallback.
- Минусы: три кодовых пути, матрица тестов.
- Нейтрально: ffmpeg остаётся общим энкодером.

### Альтернативы

- Только ffmpeg: проще, но macOS system audio/Wayland страдают.
- Только нативные: дорого и хрупко.

## ADR-010 — Качество измеряется: WER/DER и корпус

**Статус:** Accepted
**Дата:** 2026-11-04

### Контекст

В 3.x качество оценивается «на слух»; CI проверяет только синтаксис.
Нельзя понять, улучшил ли новый пайплайн текст/спикеров.

### Решение

- Корпус: 2/3/4 спикера, перекрытия, шум, тихая речь, русский/английский.
- WER — `jiwer`; DER — `pyannote.metrics`.
- Gate: WER ≤ 10%, DER ≤ 15%, ложная тишина ≤ 2%.
- Отчёт в CI/артефактах; сравнение с baseline.

### Последствия

- Плюсы: объективные решения, защита от регрессий.
- Минусы: размеченный корпус и время на прогон.
- Нейтрально: корпус расширяется.

### Альтернативы

- Ручная оценка: субъективно.
- Только unit-тесты: не ловят деградацию качества.

## ADR-011 — Vosk как fallback, не основной движок

**Статус:** Accepted
**Дата:** 2026-11-04

### Контекст

Vosk лёгкий и офлайн, но не даёт диаризацию и уступает faster-whisper.
В 3.x при выборе Vosk диаризация молча отключается.

### Решение

Оставить Vosk как явный fallback для слабых машин/быстрого старта. В UI
писать «спикеры недоступны с Vosk», не отключать молча. Основной движок —
faster-whisper.

### Последствия

- Плюсы: выбор для пользователя, меньше зависимостей.
- Минусы: два пайплайна; тесты для обоих.
- Нейтрально: можно удалить позже по метрикам.

## ADR-012 — Ошибки как коды + пользовательская подсказка

**Статус:** Accepted
**Дата:** 2026-11-04

### Контекст

В 3.x ошибки — строки/`print`, пользователь видит «не удалось», логи
разбросаны. Нельзя стабильно тестировать и локализовать.

### Решение

Единый `AppError { code, user_message, hint, technical, retryable }`.
UI показывает сообщение и подсказку; код — в лог/телеметрию. Справочник
кодов — в документации.

### Последствия

- Плюсы: одинаковые сообщения, проще поддержка/тесты.
- Минусы: дисциплина, справочник.
- Нейтрально: технические детали в «Подробнее».

## ADR-013 — JSON-RPC 2.0 между Rust и Python sidecar

**Статус:** Accepted
**Дата:** 2026-11-04

### Контекст

Нужно изолировать ML, не тащить Python-объекты в Rust и не открывать
локальный HTTP-сервер (порты, безопасность, firewall).

### Решение

Долгоживущий sidecar-процесс, JSON-RPC 2.0 поверх stdio, newline-delimited
JSON. Методы: `hello`, `asr.transcribe`, `diarize.run`, `speaker.embed`,
`models.*`, `cancel`, `shutdown`. Прогресс — notifications. Версия протокола
проверяется при `hello`. stderr — только логи.

### Последствия

- Плюсы: нет сети, просто тестировать, легко мокать, процесс изолирован.
- Минусы: нужно управлять жизненным циклом/таймаутами/рестартом.
- Митигация: supervisor, backoff, health check, contract-тесты.

### Альтернативы

- Локальный HTTP: порты/безопасность/firewall.
- Встраивание Python (PyO3): сложная сборка, GIL, падения.
- CLI на каждый файл: медленно (загрузка моделей).

**Статус:** Accepted
**Дата:** 2026-11-04

### Контекст

Нужно начать заново, не потеряв рабочую 3.2.194 и не переписывая историю.

- Нейтрально: можно позже выделить отдельный репозиторий.

## ADR-015 — Rust как язык ядра (Go — альтернатива)

**Статус:** Accepted (Rust); Go — альтернатива
**Дата:** 2026-11-04

### Контекст

Нужны производительность, кроссплатформенность и нативные API захвата
экрана/звука. Пользователь допускает Rust или Go.

### Решение

Rust как основной язык ядра. Причины:
- зрелые крейты `windows`, `objc2`, `ashpd`, `pipewire`, `cpal`;
- нет GC, предсказуемые задержки;
- безопасная работа с памятью;
- хорошая интеграция с нативным UI (egui).

Go + Wails остаётся допустимой альтернативой: проще язык, но больше
cgo/внешних утилит для capture/audio.

### Последствия

- Плюсы: меньше риск в самой сложной части (capture/audio).
- Минусы: выше порог входа, дольше разработка.
- Митигация: spike на этапе 1, переиспользование Python ML.

### Альтернативы

- Go + Wails: проще, но слабее native-экосистема.
- Python + PySide6: быстрый старт, но проблемы 3.x.
